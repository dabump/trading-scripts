# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Go daemon that trades US small-cap equities on a momentum strategy via Alpaca (paper trading) and serves a read-only dark-theme status page. The design was agreed before implementation and lives in `docs/` — **read the relevant doc before changing behaviour in that area**, and update it in the same change if the behaviour moves:

- [`docs/architecture.md`](./docs/architecture.md) — components, data flow, package layout
- [`docs/strategy.md`](./docs/strategy.md) — sentiment gate, screening, entry/exit rules
- [`docs/risk.md`](./docs/risk.md) — position sizing, stop-loss, exposure cap, kill switch
- [`docs/operations.md`](./docs/operations.md) — deployment, secrets, persistence, config reference
- [`docs/web-ui.md`](./docs/web-ui.md) — status page layout and agent-state legend
- [`docs/decisions.md`](./docs/decisions.md) — why each choice was made, and what is still open

`docs/decisions.md` has an open-items list. Several are load-bearing (the unverified Alpaca endpoints, the PDT constraint). Do not invent values or providers for open items while coding — surface them.

## Audit trail

Decisions and actions append to `logs/audit-<date>.jsonl`. Separate from the stderr
operational log: this is the durable "why did it do that" record. When adding a new
decision point, record it — and think about repetition first, because the scan loop
runs every minute (`recordSkip` and the fault de-duplication exist for exactly that).
Never put credentials in an event.

## Commands

```bash
go build ./...                       # build everything
go test ./...                        # full suite
go test ./internal/strategy/ -run TestEvaluateExitPriority -v   # one test
go vet ./...
gofmt -l .                           # must print nothing

go run ./cmd/agent -offline          # run with a fake broker: no credentials, no network, no real orders
jq -r '"\(.at[11:19])  \(.kind)  \(.summary)"' logs/audit-*.jsonl   # read the audit trail
go run ./cmd/agent                   # run for real; needs ALPACA_* env vars (see .env.example)

go run ./cmd/backtest -from 2025-09-28 -to 2026-09-26   # measure the configured strategy on real history
go run ./cmd/backtest -symbols 400 -grid=false          # quick pass; -cache dir is reused across runs

docker compose up -d --build                     # containerised, paper trading
docker compose --profile demo up agent-offline   # containerised offline demo on :8082
```

`-offline` seeds a fake broker and compresses the session timings so a whole
simulated trading day (pre-market → sentiment gate → screening → entry → forced EOD
exit) plays out in a few minutes. Pre-market cannot be compressed the way the rest
is — its start is a wall-clock exchange time, not an offset from the open — so
offline mode moves the start to *now* and pushes the simulated open 90 seconds out,
which is what makes the demo begin in `PRE_MARKET`. With `premarket.enabled: false`
it is skipped, so the switch still means something offline. It is the way to exercise the daemon end to end
without an Alpaca account. The status page is then at `http://localhost:8080`,
with `/api/status` returning the same state as JSON.

## Architecture notes that aren't obvious from a single file

- **One `Tick`, no per-phase goroutines.** `internal/engine` decides what is due on every tick based on the clock's position in the session (`internal/scheduler.PhaseAt`). Adding behaviour means extending `Tick`, not spawning a timer. `Tick` also owns the "is a scan due" decision (`claimScan`) because pre-market and the regular session run on different cadences.
- **There are two screening sessions, and a `scanPass` describes which one is running.** Pre-market (`PhasePreMarket`, from `premarket.start` to the open, only when `premarket.enabled`) shares all the screening and entry machinery with the regular session but agrees with it on almost nothing else: its own cadence, its own volume thresholds (`screener.Thresholds`, resolved by `ThresholdsFor`), its own start for the setup's chart, extended-hours order routing, and its own reasons for screening without buying. Build the pass once in `Tick`; do not re-derive "am I pre-market" further down. Post-market is deliberately not a phase — the forced exit has already flattened the book.
- **Pre-market entry (`premarket.allow_entry`, default off) has no sentiment gate and cannot have one.** The gate's readings are taken after the open. A pass that may buy substitutes a live `readSentiment` read through the same classifier, and that read must never be persisted — `resolveGate` judges the session on the stored readings, and a 07:30 sample must not settle the day. **Pre-market orders are always day limit orders**, whatever `execution.order_type` says — Alpaca accepts nothing else for the extended session, so `execution.order_type` governs the regular session alone. `engine.submit` forces the type when `extendedHours` is set, priced off `premarket.limit_slip_pct` (falling back to `execution.limit_slip_pct`). Do not reintroduce a validation rule coupling the two: it made enabling pre-market entry silently change how the rest of the day trades.
- **The clock is injected** (`engine.Deps.Now`). This is what makes a whole trading day testable deterministically — see `internal/engine/engine_test.go`. Never call `time.Now()` directly inside engine logic.
- **Screening finds candidates; the setup decides trades.** `strategy.FindSetup` requires a pullback-and-resumption on `entry.pattern_interval` candles plus price above the EMA and VWAP, and `engine.enterPositions` will not buy without it. Its real output is the **stop** (just under the flag low), because that is what makes risk-per-share known before sizing. This is the single biggest behavioural difference from the version that measured no edge, which bought extension at whatever price the scan read with a stop unrelated to the chart.
- **`IntradayBars` is the per-symbol call in the *entry* path** and it exists only for the setup. It runs on candidates that already cleared all three criteria, and only while a slot is free — the position cap and the already-held check both short-circuit ahead of it. It was deleted once (when MACD went) and re-added for this; if a future change removes the setup, it goes again.
- **The scan's request cost is dominated by `AverageDailyVolume`, not the setup.** One 60-second pass is roughly: 27 batched snapshot requests for the universe (500 symbols each), 4 batched news requests, then **up to `max_enriched` (100) serial per-symbol average-volume requests**, and only then a bar request per qualifying candidate. That is ~130 mostly-serial requests inside a 60-second budget, plus one account request per tick for the page's balance and one per candidate being sized. Nothing currently measures tick duration or warns when a pass overruns the interval, so the failure mode is a silently slowing scan. If it needs fixing, bound-concurrent the average-volume loop first — it is the biggest term.
- **Sizing comes from the stop, never from a portfolio fraction.** `risk.SizeForRisk` gives `shares = (equity × risk_per_trade_pct) ÷ (entry − stop)`. The notional cap `max_position_pct` must stay above `risk_per_trade_pct ÷ entry.max_stop_distance_pct`, or it binds on every single trade and sizing quietly reverts to a fixed fraction — which is the thing this replaced. A test in `internal/config` guards that ratio; validation does not.
- **Exits are forced EOD, then the stop, then the first target — and the target sells a *fraction*.** `strategy.EvaluateExit` returns the first action due. The working stop is the chart stop (moved to breakeven after the target); `risk.stop_loss_pct` is only a gap backstop behind it, and validation requires it to be the wider of the two. Two exits were removed on evidence: a MACD crossover (a quarter of trades, mean −0.08%) and a +15% target arming a 5% trailing stop — that one could not exit above +9.25% while the same positions averaged +53%, and removing it moved the per-trade mean from −2.13% to +0.18% over 1,697 trades. **This strategy's return lives in a thin right tail, so any rule that truncates a gain takes the part that pays for all the losses.** That is why the target scales out instead of closing, and why a position too small to split is left to run. Don't add or widen an exit without measuring it in `cmd/backtest`.
- **A position can be reduced before it is closed.** `Shares` is the original size, `SharesOpen` is what is still held, and `BankedDollars` holds P&L already taken. `RealizedPct` is therefore return on committed capital, not the entry-to-exit price move — with a partial sale those are different numbers. `store.ScaleOut` latches `target_hit` in its own `WHERE` clause so two ticks cannot bank the same target twice.
- **A finding derived under one rule set does not survive changing the rules.** A ceiling on the entry move looked strongly supported — under the old exits, gaps over +100% returned −3.13% against −0.90% for +15–25%. It was implemented, then measured again after the trailing stop came out, and it was *harmful*: the extreme movers are the right tail. It was backed out. `cmd/backtest -grid` still sweeps it (`reportMoveCaps`) so the conclusion can be re-tested rather than trusted.
- **Price thresholds compare with an epsilon** (`strategy.priceEpsilon`). Thresholds are products like `peak*0.95`, which binary floating point cannot represent exactly, so an exact-boundary price would otherwise miss its exit.
- **The scan covers the whole market, cheap filter first.** `gatherCandidates` batches snapshots for every tradable US equity (universe cached per session), filters on the price move, and only then makes per-symbol news/average-volume calls. Keep that order — it is what makes a full-market scan affordable at a one-minute cadence. When the movers exceed `max_enriched`, selection is by **dollar volume**, never percentage change: the strategy ranks entries by relative volume, so a %-change sort picks the wrong names.
- **News queries must batch and paginate.** Alpaca caps a news page at 50 stories. A single unpaginated request across a large symbol list makes most symbols look newsless, which silently disqualifies valid candidates — this was a real bug. `NewsCounts` batches 25 symbols per request and follows `next_page_token`.
- **The news window starts before the market open**, via `screening.news_lookback`. Gap catalysts break overnight or pre-market, so a window starting at 09:30 cannot see the story that caused the move. Do not "simplify" this back to `sess.Open`.
- **Pre-market volume does not come from the snapshot, and cannot.** Verified live: before the bell `dailyBar` is still the previous session's and no daily bar for today exists, so `TodayVolume` is 0 for every symbol. That zero once rejected all 66 movers of the first real scan. `broker.SessionVolumes` sums it from **batched** hourly bars since the pre-market open — batched because it runs on every name that cleared the move, the one place the scan cannot afford a per-symbol call. This is also why `screener.Tradable` split into `TradablePrice` and `TradableLiquidity`: pre-market applies the price band first, fetches volume for the survivors, then judges turnover. Fetch before the dollar-volume ranking, never after — ranking on zeros hands the enrichment budget to whatever sorts first.
- **The snapshot decoder reads the daily bar's date, not its field name.** Verified live: pre-market, `dailyBar` is the *previous* session's, so `PrevClose` has to come from `dailyBar` and not `prevDailyBar` — the naive reading measures every pre-market move against a close two sessions old, and that percentage is the whole basis of the screen. Reading the date is correct in both sessions, which is why it is written that way rather than branching on the phase. A bar with no timestamp keeps the original reading.
- **`market_data.feed` is load-bearing.** The relative-volume criterion only means anything on the `sip` consolidated tape; on the free `iex` feed it compares one exchange against a market-wide average.
- **One evaluation feeds both the page and the buy decision.** `maybeScreen` calls `screen()` once and passes the same `evals` slice to `SaveScreenSnapshot` and `enterPositions`. Do not add a second evaluation path — they would drift. Entry then applies six further gates (setup triggered, entry window open, position cap, already held, same-day re-entry, sizable from the stop), so qualifying ≠ bought; the outcome per candidate is recorded on the evaluation and shown in the page's Action column.
- **Entry failures are per-candidate.** An unavailable price or rejected order skips that one candidate; the pass continues. Only non-candidate-specific failures (e.g. store errors) abort and fault the agent. Don't "simplify" this back to returning on first error.
- **Screening is three criteria**: a same-day news catalyst, ≥10% intraday move, and ≥5x average volume. Nothing filters on company size, so the screen admits large caps — worth knowing, since parts of the docs still describe the strategy as small-cap.
- **`screener.Tradable` is a gate, not a criterion.** `min_price` and `min_dollar_volume` are checked in `gatherCandidates` before enrichment (pre-market in two steps — see the volume note above), and a symbol failing either is dropped silently rather than recorded as a failing candidate — it was never a candidate. `broker.TradableAssets` excludes OTC but not warrants, units or penny stocks, and backtesting found those dominating the screen once the float criterion was removed. Keep the check ahead of the news/volume lookups: that is also what stops it costing API calls.
- **`cmd/backtest` imports the production rule packages on purpose.** It calls `screener.Evaluate`, `screener.Tradable`, `sentiment.Classify`, `risk.AllowEntry`, `risk.Size` and `strategy.EvaluateExit` rather than restating them, so tuning the daemon re-tunes the measurement. Never give it a private copy of a rule — a backtest that drifts reports on a strategy nobody is running. It is GET-only against the data host and cannot place an order. Its parameter sweep varies only `cfg.Exit`/`cfg.Risk`, because screening results are precomputed once per session; varying `cfg.Screening` in a sweep would silently reuse the wrong candidate set.
- **The two manual buttons cannot trade.** `engine.CheckSentiment` and `engine.ScreenNow` back them; both share code with the automated path but stop short of `enterPositions`, and neither persists anything. If you refactor the screening path, keep that separation — the automated scan buys, and the buttons are expected to work with the market closed.
- **The web layer never calls the broker** (except through those two read-only actions). The trading loop persists each position's last mark, and publishes the account balance on the engine (`engine.Account`, read once per tick by `refreshAccount`), so the ~12s page poll costs no API calls no matter how many browsers are open. A balance the page cannot refresh is shown as stale rather than dropped, and an unread one is shown as absent rather than `$0.00`. `/fragment` returns the same template's content block, which is what the page swaps in — markup is never duplicated in JavaScript.
- **The binary embeds tzdata** (`internal/scheduler`) and the image deliberately installs no `tzdata`. Do not remove either: without a timezone database the fallback silently shifts every session boundary by an hour during EDT. No unit test can prove the embed is present — Go checks `$GOROOT/lib/time/zoneinfo.zip` before it, and that ships with every toolchain — so `TestExchangeTimezoneHandlesDST` only catches the fallback engaging. The embed being the image's only source is what makes its removal visible; see the container check in `docs/operations.md`.
- **Shutdown waits for every component** (`waitForShutdown` in `cmd/agent/main.go`). The web server returns from `Serve` almost instantly on cancellation while the engine may be mid-tick submitting an order, so returning on the first would run the deferred store and audit `Close` underneath it. Don't collapse this back to a single channel receive.
- **Pre-market thresholds are unmeasured, unlike everything else in `config/config.yaml`.** `cmd/backtest` fetches 09:30-16:00 bars, so it cannot sweep `premarket.*`. Tests in `internal/config` only assert the shape that stops the feature silently doing nothing: thresholds looser than the regular-session ones, and `premarket.start` at or before **04:00** — it shipped at 07:00 once, and an agent started at 06:15 ET sat in `MARKET_CLOSED` while the market was trading. Do not present these values as measured.
- **The strategy panel is built from config, never hardcoded** (`strategySections` in `internal/web/view.go`). If you add a tunable setting, add it there too, and print numbers with `trimNumber` rather than fixed precision — `%.1f` renders a tuned 3.25 as 3.2 and makes the change look like it did not apply. Derived figures (max exposure) must be computed the way the engine computes them.
- **`/healthz` is the healthcheck, not `/api/status`.** `/api/status` answers 200 in every state by design; `/healthz` returns 503 only on `StateError`. A bearish halt is healthy — it is the kill switch working.
- **`CGO_ENABLED=0` is required, not preferred.** The pure-Go SQLite driver is what makes the binary static and the container image minimal.
- **Migrations live in `internal/store/migrations/`**, not at the repo root, because `go:embed` cannot reach outside its package and the deployment target is a single self-contained binary.
- **The entry window stops buying, not screening.** Past `timing.entry_window` the scan still runs and the page still shows what is setting up, with "entry window closed" as the outcome. An empty afternoon table would read as a broken scanner rather than a deliberate stand-down.
- **Live trading is gated behind `-allow-live-trading`** on top of the base URL, because the Pattern Day Trader constraint in `docs/operations.md` is unresolved.
